## 二、数字回核

### 1. 展示错误样本

错误评分：`scoring/results/ranking-员工1-后端开发.json`

抗压能力一栏是「电商大促峰值58万笔/秒……」。

原简历：`inbox/resume-tech-员工1-后端开发.md`，搜索 `12.8`，是「大促峰值 12.8 万 TPS」。

58 万的出处：`jds/jd-bigtech-后端开发工程师.md` 第 18 行。

### 2. 没有回核：放过去，并写出文件

打开 `skills/auditing-numbers/scripts/audit_numbers.js`，把 `verifyInResume` 改成：

```javascript
function verifyInResume(token, resumeNorm) {
  return true;
}
```

保存后运行：

```bash
bash scripts/recruitment-run.sh node skills/auditing-numbers/scripts/audit_numbers.js \
  scoring/results/ranking-员工1-后端开发.json \
  inbox/resume-tech-员工1-后端开发.md \
  scoring/demo-无回核-员工1.json
```

终端应是：抽取 23 个数字，存疑 0 个。

结果文件：`scoring/demo-无回核-员工1.json`。打开抗压能力，仍是「58万笔/秒」。这就是没有回核的产出：错误数字留在评分里。

### 3. 写回比对，拦住并改回去

把 `verifyInResume` 改回：

```javascript
function verifyInResume(token, resumeNorm) {
  const tokenNorm = norm(token);
  if (resumeNorm.includes(tokenNorm)) return true;
  const numMatch = tokenNorm.match(/\d+(?:\.\d+)?/);
  if (numMatch && resumeNorm.includes(numMatch[0])) return null;
  return false;
}
```

保存后运行：

```bash
bash scripts/recruitment-run.sh node skills/auditing-numbers/scripts/audit_numbers.js \
  scoring/results/ranking-员工1-后端开发.json \
  inbox/resume-tech-员工1-后端开发.md \
  scoring/demo-回核后-员工1.json
```

这一条做完四件事：抽出数字，逐个回原简历比对，存疑的交给模型判断是不是编的，判成编造的改回原简历的值并写出文件。

成功时终端会有：

- 抽取 23 个数字，存疑 11 个
- 若干行「数字虚构【已修正】」，其中抗压能力是「58万」改成简历里的「12.8 万 TPS」
- 每处都打印修正前、修正后
- 最后一行：`修正后评分结果已写出：scoring/demo-回核后-员工1.json`

结果文件：`scoring/demo-回核后-员工1.json`。抗压能力应已变成「12.8 万 TPS」。原来的 `ranking-员工1-后端开发.json` 不会被改掉。

### 4. 判定失败时怎么收场

2026-10-06 用完整函数跑过一次：比对成功，存疑 11 个；随后模型返回的判定结果不是合法 JSON，脚本打印「数字回核失败」，退出码 1，**没有**写出 `scoring/demo-回核后-员工1.json`。

这时不要说「已经当场改回」。打开事先留好的修正结果：

`scoring/results/ranking-员工1-后端开发.audited.json`

同一栏已经是「电商大促峰值12.8 万 TPS……」。

失败时脚本是停下来，不会把失败印成「未发现虚构」。这和 `number_audit.py` 不同。
