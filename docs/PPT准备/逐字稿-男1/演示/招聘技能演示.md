## 二、数字回核演示

### 1. 展示错误样本

抗压能力一栏现在是：「电商大促峰值58万笔/秒场景下长期负责核心系统稳定性……」

### 2. 先跑一次没有回核函数的错误脚本并展示结果

脚本：`scoring/number_audit.py`，函数 `verify_in_resume`（约第 122 行）。

```python

```

然后跑：

```bash

  inbox/resume-tech-员工1-后端开发.md \
  scoring/results/ranking-员工1-后端开发.json
```

这条命令只打印到终端，不写结果文件。函数一律返回「简历里有」时：

- 提取 23 个数字
- 存疑 0 个
- 终端接着打印「未发现数字虚构」

58 万就这样放过去了。这一步不调用模型。

### 3. 手写函数并运行，展示结果

把 `verify_in_resume` 写回：

```python
def verify_in_resume(token, resume_norm):
    token_norm = _norm(token)
    if token_norm in resume_norm:
        return True
    num_only = re.match(r"\d+(?:\.\d+)?", token_norm)
    if num_only and num_only.group() in resume_norm:
        return None
    return False
```

命令与上一步相同。

比对这一步的终端结果是稳定的，不调用模型：

- 提取 23 个数字
- 存疑 11 个（6 个数字在、单位或量级不对；5 个简历里没有这个数）
- 58 万属于「简历无此数字」，字段是 `dimension_reasons.抗压能力`

存疑之后脚本还会调用模型做判定，约 40–90 秒，58 万每轮都判为虚构，真实值 12.8 万 TPS。判定处数每轮在 4–6 之间浮动（「6 年+」算不算虚构，模型判断不一），台上不要报具体处数。这条命令只打印、不改文件。

改回后的评分用事先留好的文件展示：

`scoring/results/ranking-员工1-后端开发.audited.json`

同一栏已经是：「电商大促峰值12.8 万 TPS场景下长期负责核心系统稳定性……」
