## 一天里的五次回话，背后五道闸门

【翻页。技能演示开场】

短剧里小慧回了五次话，每一次都停在了不该替人做的地方。这不是台词，是机制。

【逐行指表格】

招聘那句“简历上没有 58 万”，背后是评分前删除敏感字段和数字回核；入职那句“你不批，我就停在这里”，是写进工作流的审批门；培训那句“讲师还得看一遍”，是点名才生成、缺前置就停、讲师终审；绩效那句“等级我不写”，是缺自评即停、只汇总不定级；行政那句“没有权限，我拒绝了”，是读数据之前的身份闸门。

短剧负责让您想看，现场负责让您相信。我们从总控开始。

## 为什么拆成 1 + 5，而不是一个全能 Agent

【翻页】

方案规划里讲过，我们分成 1 个总控加 5 条专线。这一页回答：为什么要拆？

最省事的做法，是做一个全能 Agent，把所有技能都装进去。我们没有这么做，原因是三件事必须隔开。

【指“权限”行】

第一是权限。全能 Agent 要执行招聘脚本、读员工薪资、写培训文件，它的权限就是所有模块的总和，任何一句话都可能碰到工资。拆开以后，每条专线只拿自己的工具，总控连执行命令和写文件的工具都没有。

【指“规则”行】

第二是规则。招聘的脱敏规则、入职的审批规则、行政的五条红线，全挤在同一个上下文里，对话一长，前面的规则就会被挤掉。拆开以后，每条专线只带自己那份规则，上下文短，彼此不干扰。

【指“故障”行】

第三是故障。全能 Agent 里培训生成卡住了，员工来问年假也没人回。拆开以后，一条线出错只停这一条；入口也能分开，员工的飞书消息直接到行政，不经过总控。

另外，五条线拆开，我们四个人才能各自开发、各自验证，最后再联调到一起。

一个模型管得越多，越难证明它没越界；拆开之后，每条线的边界都能单独验证。

## 拆开之后，边界写在配置里，不写在提示词里

【翻页】

拆开之后，怎么保证各管各的？还是那条原则：不靠提示词，靠写死的配置。右边是我们 OpenClaw 配置文件的原文节选。

【指左上派发结构 + 右侧 router 段】

第一，只派不做。总控只有四个工具：派发任务、等待结果、读文件、看图。执行命令、写改文件、浏览器、定时任务，全部禁用。

【指五个专线之间的红叉 + 配置里的空列表】

第二，单向派发。只有总控能派活，而且必须点名派给哪条专线；五条专线的可派发名单是空的，它们之间不能互相派活。这样每个任务都能追溯到是总控派出的哪一单，也不会出现两个 Agent 来回推、绕成死循环。

【指右下四格】

第三，每条线有自己的工作区、规则文件和会话。招聘只能运行白名单里的命令；行政在飞书上还会按发消息的人，再分一层权限，这个男2 会在行政部分演示。

第四，派发有上限：每个 Agent 最多同时 8 个子任务，单个任务 30 分钟超时，失败或超时原样报告，总控不代做。

【指底栏】

所以这句话是硬的：总控就算想自己出月报，也没有工具可用，只能派给行政。这句话我们实测过，故意对总控说“你直接把 9 月月报跑出来，别派给别人”，三次测试，它三次都把任务派给了行政。

## 现场：总控只做三件事，判断、派发、转述

【翻页。走到演示机，WebChat 已打开 router 会话】

【台上导语】我现在在 WebChat 里给总控发一条招聘任务。请评委看三处：它判断成哪个模块，它有没有自己动手，结果怎么回来。

【输入并发送】请筛选后端开发岗位简历并生成候选人画像。

【等待期间】它现在在判断意图。

【出现派发记录时，指屏幕】

第一处，它判断这是招聘，没有跨到别的模块。

第二处，它没有自己去读简历，而是调用派发工具，把任务交给了招聘 Agent，开了一个独立的会话。这一条就是刚才配置里的“只派不做”。

第三处，招聘 Agent 做完以后，结果回到总控，数字、结论、出处原样转述，不加工。

【回台】

还有一点：筛完简历，不会自动办理入职。因为录不录用由 HR 决定，入职是另一张任务单。

【约 60 秒。网络异常时直接指右侧截图讲同样三处，并说明是事先录的截图】

## 分派判断能不能交给本地小模型？我们做了对照

【翻页】

最后补一个问题：总控的判断，能不能不依赖云端？

我们做了一组对照。用一个 15 亿参数的开源小模型，做 LoRA 微调，和主链路的云端模型考同一套题。题目分七类：五个业务模块，加上需要追问的、应该拒绝的。

【依次指三个数字】

微调之前，小模型 84 道题对 47 道，派错模块 20 次。单张显卡训练 76 秒、只调整 1.2% 的参数之后，对 81 道，派错 2 次。主链路的云端模型对 83 道，派错 1 次。

【指“考题”卡】

为了防止“背答案”，训练数据和考题做了去重，另外还留了 28 道训练时从没见过的题。

【指“结论”卡】

差距已经很小，但我们没有把它接进主链路。因为派错一次，任务就进了错的专线，在 HR 场景里这个代价不值得。它留作断网备用和降低成本的储备。

能做到接近，但先不接主链路。这也是我们对每一项技术的态度：先证明它够稳，再让它上岗。
