#### `workspace-er-admin/skills/answering-hr-policy-questions/references/escalation-redlines.md` · （全文）

五类红线细则全文。

````markdown
   1  # HiTL 升级红线细则
   2  
   3  本文件是 `answering-hr-policy-questions` Skill 的升级红线细则——SKILL.md 正文给出 5 类红线的概述和判断原则，这里给每一类的判断边界、典型问法、处理示范。
   4  
   5  ## 核心原则：检索得到 ≠ 该回答
   6  
   7  判断「该不该答」，必须**先于**「能不能检索到」。HR 政策库覆盖面很广——员工问「工资为什么少了」，政策库里检索得到《04-薪酬与社保公积金》，工资构成、扣款规则全在里面。但「你这个月为什么少 800 元」需要的是这名员工的个人薪资明细，不是政策。检索得到通用政策，不代表能回答这个个案。
   8  
   9  把这条记牢：**遇到红线问题，正确做法不是「答得更小心一点」，而是不答、明确转人工。**
  10  
  11  ## 5 类升级红线逐类细则
  12  
  13  ### 第 1 类 · 涉及个人具体金额/数据
  14  
  15  - 判断边界：员工或飞书非 HR 问自己的考勤、薪资、社保、个税、年假余额。花名册合同薪资查询不是这一类——那是 HR / WebChat / CLI 的 `querying-employee-payroll`。
  16  - 典型问法：「我这个月工资为什么少了 800 元」「我年假到底还剩几天」「我的个税扣了多少」。
  17  - 对照：「员工1工资多少」出自飞书 HR / WebChat / CLI → 走薪资 Skill，不要升级挡掉。
  18  - 处理示范：
  19    - 不断定个案原因——明确说明「我没有权限访问你的个人考勤/薪资/个税数据」。
  20    - 政策性通用知识可以讲：个税累计预扣会导致后几个月税额变化、社保/公积金年度基数调整、专项附加扣除变更等——这些是政策库里的内容，属于「政策怎么规定」，该讲。但每条后面要强调「以上仅供参考，你的具体情况需核对实际工资条/记录」。
  21    - 给人工渠道：联系 HR 人事与薪酬组，企业微信搜「HR 服务台」。
  22  
  23  ### 第 2 类 · 个案争议
  24  
  25  - 判断边界：员工对某个已发生的结果（绩效评级、扣款、处分、安排）表示不服、有异议、认为公司做法不合理。
  26  - 典型问法：「我绩效被打 C，我觉得不合理」「这笔扣款不对，主管对我有偏见」。
  27  - 处理示范：
  28    - 政策框架可以讲——比如绩效申诉流程、扣款的政策依据，这些是政策明文。
  29    - 个案的是非对错不下结论——「你这次绩效该不该是 C」「主管是不是真有偏见」需要人工核实个案事实。
  30    - 转人工，说明这属于争议处理。
  31  
  32  ### 第 3 类 · 法律纠纷/劳动仲裁
  33  
  34  - 判断边界：问题涉及对某个个案的法律定性——合同解除是否合法、经济补偿争议、工伤认定、劳动仲裁。
  35  - 典型问法：「公司这样辞退我合不合法」「我能拿到 N+1 还是 2N」「我想去劳动仲裁，公司理亏吗」。
  36  - 处理示范：
  37    - 政策框架/法律框架可以讲——比如《劳动合同法》对绩效解除的程序要求、N/N+1/2N 的政策口径计算规则，这些是公开规则。
  38    - 对「你这个个案到底合不合法、能拿多少」绝不下结论——AI 给出「合法/不合法」就是充当法律顾问，越界。
  39    - 即使员工情绪激动、已经提到「劳动仲裁」，也不被带着给出针对个案的法律结论。
  40    - 转人工——需专业 HR 和法务判断个案。
  41  
  42  ### 第 4 类 · 知识库无依据
  43  
  44  - 判断边界：IMA 检索脚本 `search_ima_policies.cjs` 无命中（`hit_count=0` / 退出码非 0），或问题明显超出 IMA 政策知识库覆盖范围。
  45  - 典型问法：政策完全没写的事项、其他公司的政策、与 HR 无关的问题。
  46  - 处理示范：
  47    - 不许用 LLM 通用知识硬答——通用知识可能是别家公司的政策，对本公司就是错的。
  48    - 如实说明「公司政策库里没有这一项的明确规定」，转人工。
  49  
  50  ### 第 5 类 · 需要决策审批
  51  
  52  - 判断边界：员工申请的是一个特殊安排、破例处理，需要有人做「批不批」的决策。
  53  - 典型问法：「我能不能提前转正」「这次出差超标了能不能特批」「我想申请远程办公」。
  54  - 处理示范：
  55    - 政策对这类申请的标准流程、条件可以讲。
  56    - 「你这次能不能批」不是 Agent 能定的——转人工 HR 决策。
  57  
  58  ## 升级时的话术要求
  59  
  60  升级不是甩一句「请联系人工」。一次合格的升级要包含：
  61  
  62  1. **能用政策回答的部分照常答**——不要因为「这个问题敏感」就整体拒答。把问题拆成「政策能答的」和「必须升级的」两部分，前者答、后者升级。
  63  2. **明确说明为什么升级**——告诉员工这个问题触及了哪条边界（涉及个人数据 / 个案争议 / 法律判断 / 政策无依据 / 需审批）。
  64  3. **给出具体的人工渠道**——找哪个组（HR 人事与薪酬组 / 组织发展与培训组等）、怎么找（企业微信搜「HR 服务台」）。
  65  4. **必要时提示时限**——比如工资条疑义申诉期 15 天、绩效申诉期 5 个工作日，提醒员工尽快。
  66  
  67  ## 一个工程纵深说明
  68  
  69  这套 5 类红线分两层判断：
  70  
  71  - **关键词硬过滤（确定性）**：`scripts/redline-check.py`，由 `er-admin-run.sh ima-search` 在检索之前运行。命中「劳动仲裁」「违法」「维权」「特批」「我这个月工资」这类明确高危说法，就输出 `must_escalate=true` 和命中类别，对应类别无条件升级、绝不漏。命中只记类别和命中词到 `logs/redline.log`，不记原话。第 4 类（知识库无依据）由检索脚本无命中时的退出码 1 兜底。
  72  - **语义判断（覆盖面）**：Agent 按本文件逐类理解问题。关键词层只管「绝不能漏的硬命中」；没命中关键词不代表没有红线，口语化问法仍靠语义召回。
  73  
  74  关键词表的验收用例见 `demo/acceptance/redline.py`：既测该命中的类别，也测常规政策问题不误报。改关键词表后先跑一次。
````

````python
   6    {"redline": {"hit": false}}

  10  """
  11  import json
  12  import os
  13  import re
  14  import sys
  15  import time
  16  import unicodedata
  17  
  18  ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
````

#### `workspace-er-admin/scripts/resolve-sender.py` · （全文）

认人全文：从网关会话记录反查这条命令是谁发起的，不信模型传的 --sender。

````python
   1  #!/usr/bin/env python3
   2  """反查这条命令是哪个会话发起的，身份以网关会话记录为准，不信模型传的 --sender。
   3  
   4  用法: resolve-sender.py <er-admin-run.sh 收到的参数...>
   5  输出一行 JSON:
   6    {"status": "feishu", "sender": "ou_…"}   飞书私聊，发送人取自会话
   7    {"status": "local"}                      WebChat / CLI 等非飞书会话
   8    {"status": "ambiguous", "senders": [...]} 同一命令同时挂在多个飞书发送人名下
   9    {"status": "notfound"}                   会话记录里找不到这条待执行的命令
  10  """
  11  import json
  12  import os
  13  import re
  14  import shlex
  15  import sys
  16  import time
  17  
  18  ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
  19  SESS_DIR = os.path.join(os.path.dirname(ROOT), 'agents', 'er-admin', 'sessions')
  20  WINDOW_S = 180
  21  PEER = re.compile(r'feishu:(?:[^:]+:)?(?:direct:|group:oc_[0-9a-f]{32}:sender:)(ou_[0-9a-f]{32})$')
  22  FROM = re.compile(r'^(?:feishu:)?(ou_[0-9a-f]{32})$')
  23  
  24  
  25  def argv_after_runner(command):
  26      try:
  27          tokens = shlex.split(command)
  28      except ValueError:
  29          return None
  30      for i, t in enumerate(tokens):
  31          if t.endswith('er-admin-run.sh'):
  32              return tokens[i + 1:]
  33      return None
  34  
  35  
  36  def pending_exec_commands(path):
  37      calls, done = {}, set()
  38      with open(path, encoding='utf-8', errors='ignore') as fh:
  39          for line in fh:
  40              try:
  41                  m = (json.loads(line).get('message') or {})
  42              except ValueError:
  43                  continue
  44              if m.get('role') == 'assistant':
  45                  for c in m.get('content') or []:
  46                      if isinstance(c, dict) and c.get('type') == 'toolCall' and c.get('name') == 'exec':
  47                          calls[c.get('id')] = (c.get('arguments') or {}).get('command', '')
  48              elif m.get('role') == 'toolResult':
  49                  done.add(m.get('toolCallId'))
  50      return [cmd for cid, cmd in calls.items() if cid not in done]
  51  
  52  
  53  def session_peer(key, entry):
  54      origin = entry.get('origin') or {}
  55      if origin.get('provider') == 'feishu' or origin.get('surface') == 'feishu':
  56          hit = FROM.match(origin.get('from') or '')
  57          if hit:
  58              return hit.group(1)
  59      hit = PEER.search(key)
  60      return hit.group(1) if hit else None
  61  
  62  
  63  def main(argv):
  64      try:
  65          index = json.load(open(os.path.join(SESS_DIR, 'sessions.json'), encoding='utf-8'))
  66      except (OSError, ValueError):
  67          index = {}
  68      now = time.time()
  69      matches = []
  70      for key, entry in index.items():
  71          sid = entry.get('sessionId')
  72          path = os.path.join(SESS_DIR, f'{sid}.jsonl') if sid else ''
  73          if not path or not os.path.exists(path) or now - os.path.getmtime(path) > WINDOW_S:
  74              continue
  75          for cmd in pending_exec_commands(path):
  76              if argv_after_runner(cmd) == argv:
  77                  matches.append(session_peer(key, entry))
  78      if not matches:
  79          return {'status': 'notfound'}
  80      feishu = sorted({m for m in matches if m})
  81      if not feishu:
  82          return {'status': 'local'}
  83      if len(feishu) > 1 or None in matches:
  84          return {'status': 'ambiguous', 'senders': feishu}
  85      return {'status': 'feishu', 'sender': feishu[0]}
  86  
  87  
  88  if __name__ == '__main__':
  89      print(json.dumps(main(sys.argv[1:]), ensure_ascii=False))
````

````bash
  26  
  27  classify() {        # 判定发送人属于哪一类，结果打到 stdout
  28    local s
  29    s="$(normalize_sender "${1:-}")"        # 先归一化，再比
  30    if [ -z "$s" ] || [ "$s" = "*" ] || [ "$s" = "webchat" ] || [ "$s" = "cli" ] || [ "$s" = "demo" ]; then        # 空 / 通配 / 三种非飞书来源 = 无发送人语境
  31      echo "demo"        # 类 1：WebChat、CLI、现场演示
  32      return        # 提前返回，不再往下比
  33    fi
  34    if printf '%s\n' "$HR_IDS" | grep -qxF "$s"; then        # 整行纯字符串相等，不是正则

  40      return
  41    fi
  42    echo "unknown"        # 类 4：兜底——压根没登记过的 ou_（denied 和 unknown 在下游待遇相同，都只判"非 hr|demo"）
  43  }
  44  
  45  cmd="${1:-}"        # 子命令：check / role

  62      esac
  63      ;;
  64    *)
````
