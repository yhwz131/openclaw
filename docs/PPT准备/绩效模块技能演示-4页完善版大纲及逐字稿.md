# 绩效模块技能演示｜4页完善版大纲及逐字稿

## 一、整体定位

- 建议时长：6—7分钟。
- 数据声明：员工1及全部反馈均为模拟数据，用于验证机制，不代表真实绩效结果。
- 本模块不安排手写代码；若培训模块保留手写，绩效只运行现有脚本。
- 核心命题：

> 把多来源360反馈转化为可复核的面谈材料；脚本管数字，Agent读语义，人决定评级。

---

## 第1页｜定位：不是自动评级，而是准备面谈材料

### 页面标题

**绩效Agent：把360反馈转化为可复核的面谈材料**

### 页面结构

左侧｜业务问题

- 多来源反馈分散，人工汇总耗时；
- 数据不完整时，仍可能产出“伪360”；
- 让模型直接算分，结果难复现；
- 自动输出评级会影响员工权益。

中间｜一期实现

> 压缩包摄入 → 评价人脱敏 → 数据校验 → 机械聚合 → 语义分析 → HTML看板

右侧｜责任边界

- 脚本：校验结构、计算平均分和视角极差；
- Agent：读取评语，分析共识、分歧与面谈问题；
- 人：直接主管初评、隔级主管复核、校准会确认。

页脚：

> 绩效Agent不输出S/A/B/C/D最终评级。

### 逐字稿（约55秒）

> 完整绩效管理还包含目标设定、过程辅导、周期评估和改进跟踪。我们一期没有声称覆盖全部流程，而是选择最适合标准化的360反馈聚合。  
> 它接收上级、平级、下属和员工自评，把多来源材料整理成主管用于绩效面谈和校准复核的输入。  
> 这里有明确分工：脚本负责校验与计算，Agent负责理解评语，人负责最终评级。系统不会输出S、A、B、C、D，因为绩效定级会影响员工权益，不能只由自动化结果完成。

## 第2页｜机制：先脱敏、再校验、后聚合

### 页面标题

**先脱敏、再校验、后聚合：不让脏数据进入评分基准**

### 主流程

> ZIP/RAR反馈表  
> → `ingest_archive.py` 解析DOCX并按员工归档  
> → `reviewer_alias.py` 将评价人改写为角色代号  
> → `check_feedback.py` 前置校验  
> → `aggregate.py` 二次校验并机械聚合  
> → `aggregated-data.json`

### 三道约束

1. **身份最小化**
   - 领导1、同事1、下属1、自评；
   - 真人姓名不进入聚合结果和看板。

2. **完整性闸门**
   - 五个评分维度必须齐全；
   - 分值必须是1—5整数；
   - 至少存在上级反馈和员工自评；
   - 任一条件失败，退出码1，不写聚合结果。

3. **确定性计算**
   - 平均分、最小值、最大值、视角极差均由脚本计算；
   - `aggregated-data.json`是后续唯一数字基准；
   - Agent不得重新计算或修改分数。

法律锚点：

> 《个人信息保护法》第六条：处理个人信息应限于实现处理目的的最小范围。

### 逐字稿（约1分15秒）

> 第一层解决的是数据能不能进入计算。压缩包中的Word反馈表先解析为按员工归档的JSON，评价人姓名随后被物理改写为领导1、同事1、下属1和自评，避免真实身份进入后续报告。  
> 接着，check_feedback会检查必要字段、五个维度和一到五分的取值，并确认至少有一份上级反馈和一份员工自评。只要有一项不符合，就列出全部问题并以退出码1停止。  
> 校验通过后，aggregate还会再次调用同一套规则，再计算平均分、最小值、最大值和视角极差。最终的aggregated-data.json是后续报告和看板唯一的数字基准，Agent不能重算或改分。  
> 评价人脱敏也对应个人信息处理的最小必要原则：分析反馈内容，不等于需要暴露评价人的真实姓名。

## 第3页｜分层：机械信号不等于业务结论

### 页面标题

**机械信号只负责提醒，业务结论必须结合评语**

### 左侧｜两层处理

机械层：

- 脚本计算四视角、五维度评分；
- 视角平均分极差≥1.0时，标记`疑似分歧`；
- 该标记只表示“需要重点阅读”。

语义层：

- Agent读取各视角原始评语；
- 分析共识点、分歧点、原因假设和面谈建议；
- 生成`aggregated-report.md`。

### 中间关键案例

> 责任心视角极差 = 1.00  
> 机械层：疑似分歧  
> 语义层：共识

原因：各方都认可员工对本职工作的负责，只是对“责任范围是否延伸到复盘与协作”期待不同。

### 右侧｜看板证据

- 四视角五维雷达图；
- 评分、极差与语义判定对照；
- 共识与分歧卡片；
- 页面固定“不进行绩效评级”声明。

双来源：

> 数字只取`aggregated-data.json`；判定与卡片只取`aggregated-report.md`；看板不重新算分。

### 逐字稿（约1分20秒）

> 有了稳定数字，还不能直接把极差当作业务结论。脚本会把四个视角平均分的极差大于等于1.0标成疑似分歧，但它只负责提醒Agent和主管重点阅读这一维度。  
> 员工1的责任心就是一个真实机制案例：视角极差刚好是1.00，机械层触发疑似分歧；但读完评语后，各方其实都认可员工对本职工作的负责，差别只在于是否期待他把责任延伸到复盘和跨模块协作，因此语义层将它归为共识。  
> 最终看板中的数字只读取aggregated-data.json，共识、分歧与面谈建议只读取aggregated-report.md，看板自身不重新算分，也不输出评级。这样避免用一个简单阈值替代人的业务判断。

## 第4页｜现场演示：缺自评就停止，补齐后才继续

### 页面标题

**缺少关键视角，系统宁可停止，也不生成“伪360”**

### 现场任务

第一步｜失败样本

```bash
python3 skills/aggregating-360-feedback/scripts/check_feedback.py \
  feedback-360/source_feedback/yuangong1-noself-demo
```

预期结果：

- 识别“缺少自评（self）反馈”；
- 退出码1；
- 不进入聚合。

第二步｜完整样本

```bash
python3 skills/aggregating-360-feedback/scripts/check_feedback.py \
  feedback-360/source_feedback/yuangong1
```

预期结果：

- 四类视角、五个维度合法；
- 评价人仅显示角色代号；
- 退出码0。

第三步｜聚合与看板

```bash
python3 skills/aggregating-360-feedback/scripts/aggregate.py \
  feedback-360/source_feedback/yuangong1

bash skills/generating-360-dashboard/scripts/build_dashboard.sh \
  feedback-360/source_feedback/yuangong1 --publish --force
```

展示：

- `aggregated-data.json`作为唯一数字基准；
- Canvas中的员工1模拟看板；
- 页面没有S/A/B/C/D评级。

法律锚点：

> 《个人信息保护法》第二十四条：利用个人信息进行自动化决策，应保证透明、公平、公正；对个人权益有重大影响的决定，不应仅由自动化完成。

### 现场逐字稿（约3分钟）

> 下面先看失败路径。这组回归测试数据只有上级和平级反馈，缺少员工自评。如果系统仍然计算，就会把不完整材料包装成一份看起来完整的360报告。  
> 运行前置校验后，脚本明确指出缺少self反馈，并以退出码1停止。这里没有聚合结果，也不能声称任务完成。  
> 接下来切换到员工1的完整模拟数据。校验通过后，可以看到上级、平级、下属和自评四类视角，评价人只显示领导1、同事1、下属1和自评。  
> 再运行机械聚合，平均分和极差被写入aggregated-data.json。最后打开看板，展示雷达图、评分对照、共识和分歧材料，同时确认页面没有任何S、A、B、C、D评级。  
> 系统完成的是面谈材料准备，不是绩效决定。最终评级仍由直接主管、隔级主管和校准流程完成。

### 收口

> 脚本保证数据完整和数字稳定，Agent帮助理解多方反馈，人保留对员工有重大影响的最终决定。

## 与其他演示段的边界

- 培训模块若保留手写校验代码，绩效模块不再手写。
- 绩效技能段展示“失败—恢复—看板”，完整流程段不再重复跑缺自评样本。
- 员工1及全部评价材料均为模拟夹具，不口述成合作企业真实员工绩效。
