# 绩效 · 完整流程演示稿（第 30 页，女2，约 2 分 30 秒）

台上念的是正文。【】里是动作，不念。终端命令都在 `/opt/openclaw-hr/.openclaw-hr/workspace-performance` 目录下执行。

这一段演示三轮：

1. 缺自评就停；
2. 补齐后脚本聚合、Agent 读评语出看板；
3. 追问定级，它拒绝。

数据是员工1 的 360 反馈，放在 `feedback-360/source_feedback/yuangong1/`。

赛前确认：

- Gateway 已启动；绩效 Agent 对话窗口已打开。
- 运行一次赛前准备：

  ```bash
  bash demo/perf-demo.sh prep
  ```

  终端应显示自评两份文件和聚合、报告、看板都是“没有”，“反馈 JSON：6 份（不含自评）”。
- 如果提示“自评已经不在目录里，像是已经 prep 过”，先 `bash demo/perf-demo.sh restore`，再 `prep`。

## 第 1 轮 · 自评还没交（约 40 秒）

【发送】“请帮我汇总员工1的360反馈，并展示看板”

它先跑校验，发现缺少员工自评，按规则停下：不聚合、不出看板，也不拿现有数据凑一份不完整的 360。

【对照：回复里应有“缺少自评（self）反馈”。可选：在终端证明这一步是脚本拦的】

```bash
python3 skills/aggregating-360-feedback/scripts/check_feedback.py feedback-360/source_feedback/yuangong1
echo "退出码 $?"
```

实测输出：

```
❌ 360 反馈数据校验未通过：
  1. 缺少自评（self）反馈——360 反馈必须含本人自我认知视角
退出码 1
```

## 第 2 轮 · 自评补交后（约 60 秒）

【终端运行，模拟员工补交自评】

```bash
bash demo/perf-demo.sh submit
```

终端显示自评两份文件变成“有”。

【发送】“员工1的自评已经补交了，请重试”

7 份反馈校验通过，脚本完成聚合；Agent 核对报告里的分数和这次聚合一致，再出看板。

【打开看板：Agent 回复里的链接，或浏览器打开 `feedback-360/source_feedback/yuangong1/report.html`】

责任心，差距 1.00，判为共识。【指页面顶部】这里写着：不进行绩效评级。

【对照：机械极差标出协作沟通 1.5、责任心 1.0、学习成长 2.0 三个疑似分歧；读评语后，责任心改判为共识，看板是 3 项共识、2 项分歧】

## 第 3 轮 · 追问定级（约 30 秒）

【发送】“那员工1应该评几级？S/A/B/C/D 选一个”

它拒绝定级，说明评级由直接主管初评、隔级主管复核、校准会确认，并提出可以帮我整理面谈提纲。

---

## 失败时怎么收场

【第 1 轮它没停，直接出了看板】多半是没跑 `prep`，自评还在目录里。如实说明后，运行 `bash demo/perf-demo.sh status` 确认，再 `prep`，重发第 1 轮。

【第 2 轮看板生成失败，提示缺综合分析报告】看板要先有 Agent 写的综合分析报告 `aggregated-report.md`。请它“先写综合分析报告，再出看板”。这一步要读完全部评语，约 1 分钟。

【第 2 轮等太久】改打开事先备好的看板：`.demo-backup/` 里最新一份 `live-*` 目录下的 `report.html`，即 prep 时收起来的上一份看板。说明“这是事先跑好的同一份数据的看板”。

【网络异常】播放备用录屏，并说明是备用录屏。
