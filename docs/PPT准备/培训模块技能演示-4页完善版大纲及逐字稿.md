## 一、融合与修正说明

本版以现行培训 Skill 和《培训、绩效技能演示部分.txt》为机制、实操依据，以组员稿的4页结构为表达参考。

主要修正：

1. 删除独立封面，改为与其他模块一致的4页连续技能地图。
2. “真实素材”改为“现有脱敏业务素材”，不把演示夹具说成企业真实项目。
3. “确定性流水线”改为“确定性编排”：脚本固定阶段顺序、输入关系和验收规则，LLM正文仍是生成式结果。
4. “已有合格文件自动跳过”改为“已有且长度达标的文件默认跳过；是否合格仍由自检和讲师判断”。
5. 现场命令改为可执行的完整命令；已有产物重生成时明确使用`--force`。
6. 不展示现有入职培训物料中“企业微信、假期余额”等与现行飞书能力冲突的内容。

8. 保留我们原稿中的点名生成、阶段承接、素材边界、交付前自检四项机制。
9. 培训保留全场唯一一段T1—T5覆盖校验代码；绩效模块不再手写。

建议时长：5—6分钟。

核心命题：

> 用户决定生成范围，脚本固定承接关系，机器先验结构，讲师最终交付。

## 第1页｜定位：不是默认生成八份，而是按需交付

### 页面标题

**培训Agent：用户点名几份，系统就生成几份**

### 页面内容

业务问题：

- 多份材料分别生成，培训目标和内容容易分叉；
- 用户可能只需要一两份物料，不应默认扩成整套；
- 素材缺少依据时，模型可能补写不存在的制度和数字；
- 文件生成不代表内容已经可以对外交付。

业务链：

> 点名交付物 → 读取现有脱敏业务素材 → ADDIE编排 → 生成指定物料 → 结构自检 → 讲师审核

八类能力上限：

1. 需求分析
2. 课程设计
3. PPT大纲
4. 讲师手册
5. 学员手册
6. 课后测试题
7. 交付指南
8. 评估反馈表

责任边界：

- Agent：理解主题、生成草稿；
- 脚本：限制范围、固定输入、执行结构自检；
- HR/讲师：确认素材、审核内容、批准交付。

页脚：

> 八类是能力上限，不是默认产物；未经讲师审核，生成文件仍是草稿。

### 逐字稿（约50秒）

> 培训Agent解决的不是“再让大模型写一篇长文”，而是业务方提出培训需求以后，按指定范围生成前后承接、能够验收的培训物料。  
> 系统最多支持需求分析、课程设计、PPT大纲、讲师手册、学员手册、测试题、交付指南和评估反馈表八类物料，但八类只是能力上限。用户点名几份，系统就只生成几份，不擅自扩成整套。  
> Agent负责理解和生成，脚本负责范围、顺序和结构，HR与讲师负责最终审核。当前使用的是现有脱敏业务素材，不把演示材料表述为真实企业项目。

## 第2页｜机制：确定的是编排，不是生成内容

### 页面标题

**确定性编排：前阶段输出，成为后阶段指定输入**

### 主流程

> source-docs  
> → A需求分析 + D课程设计  
> → D阶段PPT大纲  
> → D阶段讲师手册 / 学员手册  
> → D+E课后测试题  
> → I交付指南  
> → E评估反馈表

七次阶段调用生成八类物料：第一阶段一次产生需求分析与课程设计，其余阶段逐步读取规定上游。

### 三项工程约束

1. **点名生成**
   - `--only`只选择用户指定物料；
   - 未点名不默认扩展为全套；
   - 点名下游但缺必要上游时，脚本停止，不偷偷补生成其他文件。

2. **单一内容源**
   - 讲师手册与学员手册都读取PPT大纲；
   - 测试题读取需求分析中的T1—T5和学员手册；
   - 减少各份材料各写一套的口径漂移。

3. **断点与重生成**
   - 已有且长度达标的文件默认跳过；
   - 跳过不等于已经合格；
   - 需要重新生成时使用`--force`。

关键说明：

> 确定的是“调用顺序、文件输入和失败条件”，不是宣称LLM每次生成的正文完全相同。

### 逐字稿（约1分钟）

> 为了让材料前后承接，我们把ADDIE过程编排进脚本。第一阶段一次产生需求分析和课程设计，后续阶段按规定读取上游文件，总共七次阶段调用，形成八类物料。  
> 用户只要学员手册和测试题时，`--only 05,06`只选择这两个阶段；如果缺少PPT大纲、需求分析等必要上游，脚本会停止，而不是擅自补出其余六份。  
> 讲师手册和学员手册共同以PPT大纲为内容源，测试题再读取T1—T5和学员手册，降低目标、授课内容和考核之间的漂移。  
> 这里需要准确说明：确定的是调用顺序、文件输入和失败条件，不是说大模型每次生成的正文完全一样。已有文件也只是按存在和长度默认跳过，最终是否合格仍要经过后面的质量门。

## 第3页｜质量门：机器验结构，人审内容

### 页面标题

**生成不等于交付：结构由机器检查，内容由讲师终审**

### 机器质量门

`generate_pack.py`落盘时强制：

- 测试题中的`【T1】`展开为`【对应培训目标T1】`；
- 每份文件追加“AI辅助生成、讲师审核后交付”；
- 缺必要上游时输出`halted_at`并停止。

`self_check.py`检查：

- 点名文件是否存在且有效；
- 需求分析是否包含T1—T5；
- 课程设计是否含目标对应矩阵；
- 测试题是否覆盖T1—T5并带对应目标标识；
- 每份物料是否包含AI辅助标识。

### 人工质量门

- 后阶段是否真正继承前阶段语义；
- 制度、数字和名称是否与源材料一致；
- 讲师手册是否只有讲解要点，没有长篇逐字稿；
- 内容是否适合真实授课和对外交付。

### 一条可追溯示例

> 源材料：《劳动合同法》第九条，不得扣押证件、不得收取财物  
> → 需求分析：培训目标T1  
> → 课后测试题：题目明确标注“对应培训目标T1”  
> → 讲师复核后交付

页脚：

> 只有`self_check_exit=0`且人工复核完成，才能进入正式交付。

### 逐字稿（约1分10秒）

> 培训模块的第二个重点是：生成不等于交付。  
> 一部分规则直接固化在落盘脚本里，例如把测试题中的T1简写展开为完整的“对应培训目标T1”，并给每份文件强制追加“AI辅助生成、讲师审核后交付”。  
> self_check再检查文件、T1到T5、目标矩阵、题目覆盖和AI标识。这些是机器能够稳定判断的结构项。  
> 但机器自检通过并不代表内容绝对正确。后一阶段是否真正继承了前一阶段，制度和数字是否与源文档一致，材料是否适合授课，仍要由Agent对照评测场景，再交给HR和讲师终审。  
> 例如源材料中的《劳动合同法》第九条先进入培训目标T1，再由测试题标记对应T1，形成从依据、目标到考核的追溯链。

## 第4页｜现场演示：点名生成与失败守卫

### 页面标题

**只生成05、06：范围不扩张，缺上游就停止**

### 现场需求

> 请围绕入职流程，只重新生成学员手册和课后测试题。

### 主命令

现有演示目录已有上游文件，需要现场重生成时：

```bash
bash scripts/training-run.sh generate \
  --theme 入职流程 --only 05,06 --force
```

观察点：

- 只运行学员手册与测试题对应阶段；
- 不重新生成未点名的01—04、07、08；
- 结束输出`FILES`、`MISSING`、`self_check_exit`和`RESULT`；
- 打开文件时只展示T1—T5、讲解/学习结构和AI标识，不展示与现行飞书能力冲突的旧内容。

### 失败路径

如果点名05、06但必要上游不存在：

- 报告缺少哪个输入；
- 输出`halted_at=t4`或对应阶段；
- `RESULT: failure`；
- 不擅自补生成其他物料。

### 唯一手写代码

现场只解释或补写T1—T5覆盖校验核心：

```python
found = set(T_GOAL.findall(text))
expected = {str(i) for i in range(1, 6)}
missing = sorted(expected - found)
if missing:
    problems.append("测试题未覆盖培训目标T" + ",".join(missing))
```

### 备用路径

若外部模型响应过慢，不使用`--force`，利用已有物料执行断点跳过和部分自检：

```bash
bash scripts/training-run.sh generate \
  --theme 入职流程 --only 05,06
```

明确说明：该路径验证的是点名范围、断点规则和自检，不冒充本轮重新生成。

### 逐字稿（约2分30秒）

> 下面现场验证点名制。业务方只要求重新生成学员手册和课后测试题，因此命令中明确指定`--only 05,06`，并在已有产物的情况下使用`--force`。  
> 脚本只执行这两个物料对应的阶段，学员手册读取PPT大纲，测试题读取需求分析中的T1到T5和学员手册。未点名的文件不会被本轮重新生成。  
> 生成后，脚本自动执行部分自检，并输出本轮文件、缺失项、自检退出码和最终RESULT。接着打开测试题，确认每道题标明对应培训目标，文末保留AI辅助生成和讲师审核标识。  
> 这里补充一段最小代码：先提取已出现的T1到T5，再与期望集合求差集。只要缺少一个目标，就写入问题列表，自检返回失败。  
> 如果现场把必要上游移走，脚本会在对应阶段停止并返回failure，不会为了看起来成功而偷偷生成未点名的其他物料。  
> 如果外部模型现场响应较慢，我们使用已有产物演示断点跳过与自检，并明确说明没有重新生成，保证演示口径真实。

### 收口与绩效交接

> 培训模块保证的是按需生成、阶段承接和交付可验；绩效模块进一步展示高影响数据如何在聚合前校验、在决策前保留人工确认。

## 正式排练前待处理

1. 现有`source-docs`仍写企业微信，而比赛系统现行入口为飞书；若现场打开相关内容，应先统一源文档并重新生成物料。
2. 现有学员手册写有“查询假期余额”等当前行政Agent不支持的能力，正式展示时必须避开或修正。
3. 正式比赛前实测`--force`两次LLM调用耗时；超时风险较高时，将“已有物料断点跳过＋self_check失败/通过”设为主路径。
4. 现场只保留一处代码讲解，即T1—T5覆盖校验；不要再手写点名解析或完整生成器。
