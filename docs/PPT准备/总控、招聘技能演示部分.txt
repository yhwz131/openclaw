总控模块介绍 PPT 第6页
首先是总控部分
总控Agent并不负责具体的业务功能实现，它只负责接收HR发布的任务并根据意图判断任务属于哪个模块，

招聘模块介绍 PPT 第7页
招聘Agent有三条链（指向图表），分别对应前面说过的画像生成、面试纪要以及人才库检索。
他们分别的作用为：
1（指向主链）：根据简历内容与招聘岗位内容生成候选人评分画像，帮助HR快速完成简历初筛
2（指向人才库链）：将候选人简历解析出的内容向量化存入本地向量人才库，根据用人要求快速筛选人才
3（指向面试链）：对面试录音进行转写并区分说话人，最后产出面试纪要

招聘Agent机制实现 PPT 第8页
我们在实现主链的业务功能时，主要发现几点问题，
年龄、性别、婚姻状况、第一学历甚至是户籍和民族等敏感字段会进入模型上下文，无法保证是否会对候选人打分造成影响（无法排除其影响评分的可能。），
还会产生幻觉将招聘信息的内容安到候选人头上，
最终产出一份带有歧视性质且错误的人物画像以及建议。（影响评分与画像的可靠性。）

为了降低上述问题影响HR最终决策的风险，我们针对这几个问题设定了专门的防范机制：
针对简历内容歧视的敏感字段脱敏
以及针对模型幻觉导致分不清简历和JD造成张冠李戴的数字回核
提高评分结果的合规性、真实性和可追溯性。同时确定了我们“以确定性脚本约束Agent非确定性产出”的设计原则，
把需要理解和分析的部分交给Agent，需要结果稳定、可检查的部分交给脚本。
一句话来说就是Agent负责理解与生成，脚本负责校验与约束，HR负责最终决策。
但这两类问题具有概率性，现场重新调用模型不一定重复出现。
因此，我们将开发过程中捕捉到的问题样本沉淀为回归测试用例。并现场运行我们设计的机制，看它能否稳定拦截和修正。

需要手写的函数内容：
verifyInResume：数字只在原简历（已归一化）里查找。
命中返回 true；数字本身在、单位或量级不同返回 null；简历里没有这个数返回 false。
function verifyInResume(token, resumeNorm) {
  const tokenNorm = norm(token);
  if (resumeNorm.includes(tokenNorm)) return true;
  const numMatch = tokenNorm.match(/\d+(?:\.\d+)?/);
  if (numMatch && resumeNorm.includes(numMatch[0])) return null;
  return false;
}
